What is actually being scored

FORMAT

One problem, four levels

Not four questions. One system, and each level adds requirements while the previous ones must keep working. You carry your own code forward.

GATING

Levels unlock in order

You must pass a level's visible unit tests before the next opens. One unfinished level caps everything above it — which is why L1 correctness is existential.

SCORE

200–600, you need 500

Higher levels weight more. 500 realistically means L1–L3 fully clean plus real progress on L4. 200 is the score for submitting nothing.

RUBRIC

Three named competencies

Rob's email names them: General Programming & Algorithms, Requirement Understanding & Implementation, and Debugging & Troubleshooting. Two of the three are not about algorithms at all.

The one structural fact worth more than any algorithm

Because the code carries forward and the spec escalates, the assessment is really testing whether your Level 1 design can absorb Level 3 and Level 4 without a rewrite. Everyone can write Level 1. The people who score 500+ wrote a Level 1 that had somewhere to put a timestamp, a TTL, and a history list before anyone asked for them. The people who score 400 wrote flat dictionaries and bare functions, then lost twenty minutes at Level 3 panic-refactoring.

    The discipline the timer is enforcing

    Minute 0 to 5: the part that decides everything

    Do not type. Do these four things:

    1. Read every visible test for Level 1 — and skim the level titles above it. The level names alone usually telegraph what is coming (a level called "Retention" means TTL; "Reporting" means top-K; "History" means time travel).
    2. Name the entities and write the record shape, with slots for metadata nobody has asked for yet.
    3. Decide where time lives. Almost every ICF problem threads a timestamp through the API. Accept it in every method from Level 1, even when Level 1 ignores it.
    4. Decide mutate-vs-append. Append-only history with a "current value" pointer costs you nothing at L1 and makes L4 nearly free.

    How to practise — build systems, do not solve problems

    The highest-return drill, and it is not LeetCode. Pick a domain, then:

    1. Implement a clean minimal version in 15–20 minutes.
    2. Invent the next plausible requirement yourself and add it without rewriting.
    3. Repeat twice more, so you have gone L1 to L4 on your own system.
    4. Then do it again in a different domain.

    After five or six of these, your default style shifts toward methods and record types rather than dicts and loops — which is precisely the thing being scored. Domains worth using, in rough order of how often they are reported: in-memory key-value store with TTL, banking / ledger (accounts, transfers, top spenders, scheduled payments, merging accounts while preserving history), file system, package manager, build system with a task DAG, text editor with undo/redo.

    Two constraints people discover too late

    Python standard library only — no NumPy, no Pandas. Be fluent in collections.defaultdict, Counter, heapq, bisect, dataclasses, and sorting by tuple key. And return types are exact — ICF tests compare literal strings like "true", "", or "alice(5), bob(3)". Read one test's expected output character by character before you write the method.

    The Debugging & Troubleshooting third of the rubric

    Named explicitly in Rob's email and the one nobody prepares. In this format it shows up as a test failing for a reason the spec did not spell out. The discipline:

    • Read the failing test's expected value first, not your code. Most failures at L1–L2 are format mismatches, not logic errors.
    • Print the whole state object, not the one variable you suspect.
    • Never panic-rewrite. If Level 3 breaks Level 1's tests, the fix is almost always one predicate applied in the wrong place — not the architecture.
    • Re-run the earlier levels' tests after every level. Regressions against previously-passing contracts are the quiet score-killer.

    1. In-memory key-value database: simplest timed-test answer. What makes it short:

    • Store every field as (value, expires_at), and use INF for "never expires". That removes every None branch, and backup/restore arithmetic still works because INF - now and now + INF are both INF.
    • defaultdict(dict) and defaultdict(list) mean writes never need "create it if missing". An empty entry means "nothing there", so it's harmless when a read creates one.
    • One read helper, _live(now, key), returns {field: value} for the fields still alive. Every read goes through it, so TTL is respected everywhere with no extra code.
    • One write helper, _put. A delete is just "expires right now", so the look-back history records deletions for free.
    • compare_*: _live(...).get(field) returns None for a missing field, and None never equals a string, so one comparison covers "missing" and "wrong value".
    • backup counts keys for free: the snapshot is a defaultdict, and a key only appears once one of its fields is alive.
    • Level 4: write ONLY the variant your test gives you (backup/restore OR get_when). Levels 1-3 never need self.hist; add it only for look-back.
    from collections import defaultdict

INF = float("inf")  # "never expires"


class InMemoryDB:
    def __init__(self):
        self.db = defaultdict(dict)    # key -> {field: (value, expires_at)}
        self.hist = defaultdict(list)  # (key, field) -> [(time, value, expires_at)]   Level 4 look-back only
        self.backups = []              # [(time, snapshot)]                           Level 4 backup only

    def _put(self, now, key, field, value, exp):  # the only write
        self.db[key][field] = (value, exp)
        self.hist[key, field].append((now, value, exp))

    def _live(self, now, key):  # the only read: {field: value} for fields still alive
        live = {}
        for field, (value, exp) in self.db[key].items():
            if now < exp:
                live[field] = value
        return live

    # Level 1
    def set(self, now, key, field, value):
        return self.set_with_ttl(now, key, field, value, INF)

    def get(self, now, key, field):
        return self._live(now, key).get(field, "")

    def delete(self, now, key, field):
        if field not in self._live(now, key):
            return "false"
        self._put(now, key, field, None, now)  # delete = "expires right now"
        return "true"

    def compare_and_set(self, now, key, field, expected, new_value):
        if self._live(now, key).get(field) != expected:
            return "false"
        self._put(now, key, field, new_value, self.db[key][field][1])  # keep the TTL
        return "true"

    def compare_and_delete(self, now, key, field, expected):
        if self._live(now, key).get(field) != expected:
            return "false"
        return self.delete(now, key, field)

    # Level 2
    def scan(self, now, key):
        return self.scan_by_prefix(now, key, "")

    def scan_by_prefix(self, now, key, prefix):
        live = self._live(now, key)
        parts = []
        for field in sorted(live):
            if field.startswith(prefix):
                parts.append(f"{field}({live[field]})")
        return ", ".join(parts)

    # Level 3
    def set_with_ttl(self, now, key, field, value, ttl):
        self._put(now, key, field, value, now + ttl)
        return ""

    # Level 4, variant A: backup / restore
    def backup(self, now):
        snap = defaultdict(dict)
        for key, fields in self.db.items():
            for field, (value, exp) in fields.items():
                if now < exp:
                    snap[key][field] = (value, exp - now)  # store the REMAINING ttl
        self.backups.append((now, snap))
        return str(len(snap))  # only keys with a live field were created

    def restore(self, now, at):
        snap = None
        for t, s in self.backups:  # keep the latest backup at or before `at`
            if t <= at:
                snap = s
        if snap is not None:
            self.db = defaultdict(dict)
            for key, fields in snap.items():
                for field, (value, remaining) in fields.items():
                    self.db[key][field] = (value, now + remaining)  # the ttl resumes from NOW
        return ""

    # Level 4, variant B: look back
    def get_when(self, now, key, field, at):
        if at == 0:
            return self.get(now, key, field)
        for t, value, exp in reversed(self.hist[key, field]):
            if t <= at:
                return value if at < exp else ""
        return ""

    Show the simplest answer (87 lines, only after your attempt)

    2. Bank: simplest timed-test answer. What makes it short:

    • _settle(now) is the first line of EVERY method. It pays any cashback due at or before now, so a payment landing at exactly its due time is already credited when the operation runs.
    • Three dicts instead of one dict of dicts: balance[id] (an id is an account iff it is in here), sent = defaultdict(int), hist = defaultdict(list). You write self.balance[a] instead of self.acc[a]["balance"], and sent and hist never need "create it if missing".
    • Payments are dicts in creation order. The delay is fixed, so creation order is also due order, and _settle is a plain loop with no heap.
    • Merge: pop the removed account's balance and sent into the kept one, then point its payments at the kept account. Pending cashback follows the money with no alias chains to chase.
    • Look-back: append (time, balance) on every change, then walk the list backwards to the first entry at or before `at`. A merged-away id logs None, so it reads as "did not exist" from that time on.
    from collections import defaultdict

DAY = 86_400_000


class Bank:
    def __init__(self):
        self.balance = {}              # id -> balance   (an id is an account iff it is here)
        self.sent = defaultdict(int)   # id -> money sent out (transfers + payments)
        self.hist = defaultdict(list)  # id -> [(time, balance or None)]   None = merged away
        self.payments = {}             # payment_id -> {"acc", "due", "cashback", "paid"}

    def _log(self, t, a):
        self.hist[a].append((t, self.balance.get(a)))  # .get: None once the id is gone

    def _settle(self, now):  # FIRST line of every method
        for p in self.payments.values():
            if not p["paid"] and p["due"] <= now:
                p["paid"] = True
                self.balance[p["acc"]] += p["cashback"]
                self._log(p["due"], p["acc"])  # history stamped at the DUE time

    # Level 1
    def create_account(self, now, a):
        self._settle(now)
        if a in self.balance:
            return "false"
        self.balance[a] = 0
        self._log(now, a)
        return "true"

    def deposit(self, now, a, amount):
        self._settle(now)
        if a not in self.balance:
            return ""
        self.balance[a] += amount
        self._log(now, a)
        return str(self.balance[a])

    def transfer(self, now, src, dst, amount):
        self._settle(now)
        if src == dst or src not in self.balance or dst not in self.balance or self.balance[src] < amount:
            return ""
        self.balance[src] -= amount
        self.balance[dst] += amount
        self.sent[src] += amount
        self._log(now, src)
        self._log(now, dst)
        return str(self.balance[src])

    # Level 2
    def top_spenders(self, now, n):
        self._settle(now)
        ranked = sorted(self.balance, key=lambda a: (-self.sent[a], a))
        result = []
        for a in ranked[:n]:
            result.append(f"{a}({self.sent[a]})")
        return result

    # Level 3
    def pay(self, now, a, amount):
        self._settle(now)
        if a not in self.balance or self.balance[a] < amount:
            return ""
        self.balance[a] -= amount
        self.sent[a] += amount  # a payment is money sent out

    4. Recipe manager: simplest timed-test answer. What makes it short:

    • Store each recipe as its LIST OF VERSIONS. The current recipe is versions[-1], so Level 4 history costs nothing extra, and update is just an append.
    • Find a name conflict with a plain scan (_taken) instead of keeping a name index in sync. There is nothing to update on rename or delete, so there is nothing to forget.
    • edit = "known user" AND update. rollback = look up the old version, then edit with it, so the conflict check and version append are reused, not rewritten.
    • Store and return copies of ingredient lists (list(...)), so a caller mutating its list can't change your stored data.
    • No defaultdict here, on purpose: "rid in self.recipes" is how you tell whether a recipe exists, and a defaultdict would create an empty recipe the first time you read a missing id.
    class RecipeManager:
    def __init__(self):
        self.recipes = {}  # id -> [(name, ingredients), ...]   every version, newest last
        self.next_id = 1
        self.users = set()

    def _taken(self, name, other_than=None):  # case-insensitive name conflict
        for rid, versions in self.recipes.items():
            if rid != other_than and versions[-1][0].lower() == name.lower():
                return True
        return False

    # Level 1
    def create(self, name, ingredients):
        if self._taken(name):
            return None
        rid = self.next_id
        self.next_id += 1  # ids are never reused
        self.recipes[rid] = [(name, list(ingredients))]
        return rid

    def get(self, rid):
        if rid not in self.recipes:
            return None
        name, ingredients = self.recipes[rid][-1]
        return (name, list(ingredients))

    def update(self, rid, name, ingredients):
        if rid not in self.recipes or self._taken(name, rid):
            return False
        self.recipes[rid].append((name, list(ingredients)))
        return True

    def delete(self, rid):
        if rid not in self.recipes:
            return False
        del self.recipes[rid]  # frees the name
        return True

    # Level 2
    def search(self, text):
        hits = []
        for rid, versions in self.recipes.items():
            if text.lower() in versions[-1][0].lower():
                hits.append(rid)
        hits.sort(key=lambda rid: (len(self.recipes[rid][-1][1]), rid))  # fewest ingredients, then id
        return hits

    # Level 3
    def add_user(self, user_id):
        if user_id in self.users:
            return False
        self.users.add(user_id)
        return True

    def edit(self, user_id, rid, name, ingredients):
        if user_id not in self.users:
            return False
        return self.update(rid, name, ingredients)

    # Level 4
    def versions(self, rid):
        result = []
        for name, ingredients in self.recipes.get(rid, []):
            result.append((name, list(ingredients)))
        return result

    def rollback(self, user_id, rid, version):
        if rid not in self.recipes or not 1 <= version <= len(self.recipes[rid]):
            return False
        name, ingredients = self.recipes[rid][version - 1]
        return self.edit(user_id, rid, name, ingredients)  # conflict check + new version for free

    5. Cloud file storage: simplest timed-test answer. What makes it short:

    • One dict, name -> (size, owner). Level 1 files have owner None, which means "no capacity limit", so Level 3 is one extra field, not a second store.
    • Compute a user's used space with a loop over files (_used) instead of keeping a counter in sync through add, copy, merge and restore.
    • largest: sort the matching names with key=(-size, name), which gives "size descending, then name ascending" in one sort.
    • Level 4 restore: check for collisions FIRST, then rebuild. Nothing is half-applied when you reject.
    • Deleting from a dict while looping over it raises an error, so loop over a copy: list(self.files.items()).
    • No defaultdict here: "name in self.files" and "user in self.capacity" are the existence checks, and a defaultdict read would silently create entries.
    class CloudStorage:
    def __init__(self):
        self.files = {}     # name -> (size, owner)   owner None = plain Level 1 file
        self.capacity = {}  # user_id -> capacity
        self.backups = {}   # user_id -> {name: size}

    def _used(self, user):
        total = 0
        for size, owner in self.files.values():
            if owner == user:
                total += size
        return total

    def _fits(self, user, size):
        return user is None or self._used(user) + size <= self.capacity[user]

    # Level 1
    def add_file(self, name, size):
        if name in self.files:
            return False
        self.files[name] = (size, None)
        return True

    def copy_file(self, source, destination):
        if source not in self.files or destination in self.files:
            return False
        size, owner = self.files[source]
        if not self._fits(owner, size):  # a copy keeps the owner and must fit
            return False
        self.files[destination] = (size, owner)
        return True

    def get_size(self, name):
        if name not in self.files:
            return None
        return self.files[name][0]

    # Level 2
    def largest(self, prefix, n):
        if n <= 0:
            return []
        names = []
        for name in self.files:
            if name.startswith(prefix):
                names.append(name)
        names.sort(key=lambda name: (-self.files[name][0], name))
        result = []
        for name in names[:n]:
            result.append(f"{name}({self.files[name][0]})")
        return result

    # Level 3
    def add_user(self, user, capacity):
        if user in self.capacity:
            return False
        self.capacity[user] = capacity
        return True

    def add_owned_file(self, user, name, size):
        if user not in self.capacity or name in self.files or not self._fits(user, size):
            return None
        self.files[name] = (size, user)
        return self.capacity[user] - self._used(user)

    # Level 4
    def merge_user(self, keep, remove):
        if keep == remove or keep not in self.capacity or remove not in self.capacity:
            return False
        for name, (size, owner) in list(self.files.items()):
            if owner == remove:
                self.files[name] = (size, keep)
        self.capacity[keep] += self.capacity.pop(remove)
        self.backups.pop(remove, None)
        return True

    def backup_user(self, user):
        if user not in self.capacity:
            return None
        saved = {}
        for name, (size, owner) in self.files.items():
            if owner == user:
                saved[name] = size
        self.backups[user] = saved
        return len(saved)

    def restore_user(self, user):
        saved = self.backups.get(user)
        if user not in self.capacity or saved is None:
            return None
        for name in saved:  # check EVERY collision before changing anything
            if name in self.files and self.files[name][1] != user:
                return None
        for name, (size, owner) in list(self.files.items()):  # a copy: we delete while looping
            if owner == user:
                del self.files[name]
        for name, size in saved.items():
            self.files[name] = (size, user)
        return len(saved)

    6. Worker hours: simplest timed-test answer. What makes it short:

    • Each worker keeps a list of COMPLETED shifts as (start, end, rate). The open shift is just clock_in (None when clocked out), so "only completed shifts count" is automatic.
    • Stamp the rate onto the shift at clock-OUT, and apply a queued promotion at clock-IN. The promotion can never land mid-shift.
    • Pay: cut each shift down to the part inside [start, end) (lo, hi), pay those minutes once, then pay again for every minute of that part that falls in a double-pay period. That's why double pay needs no special case when a shift crosses a boundary.
    • Half-open intervals everywhere ([start, end)), so [1,5) and [5,7) touch without overlapping. overlap() returns 0 for an empty or backwards interval, so no extra if is needed.
    class Worker:
    def __init__(self, position, rate):
        self.position, self.rate = position, rate
        self.promotion = None  # (position, rate), applied at the next clock-in
        self.clock_in = None   # start of the open shift, or None
        self.shifts = []       # completed shifts: (start, end, rate)


def overlap(a, b, c, d):  # length of [a, b) intersected with [c, d)
    return max(0, min(b, d) - max(a, c))


class WorkerHours:
    def __init__(self):
        self.workers = {}  # id -> Worker
        self.doubles = []  # double-pay periods: (start, end)

    # Level 1
    def add_worker(self, wid, position, rate):
        if wid in self.workers:
            return False
        self.workers[wid] = Worker(position, rate)
        return True

    def register(self, wid, now):
        w = self.workers.get(wid)
        if w is None:
            return False
        if w.clock_in is None:  # clock in
            if w.promotion:
                w.position, w.rate = w.promotion
                w.promotion = None
            w.clock_in = now
        else:                   # clock out
            w.shifts.append((w.clock_in, now, w.rate))
            w.clock_in = None
        return True

    # Level 2
    def total_time(self, wid):
        w = self.workers.get(wid)
        if w is None:
            return None
        total = 0
        for start, end, rate in w.shifts:
            total += end - start
        return total

    def top_k(self, k):
        if k <= 0:
            return []
        ranked = sorted(self.workers, key=lambda wid: (-self.total_time(wid), wid))
        return ranked[:k]

    # Level 3
    def promote(self, wid, new_position, new_rate):
        if wid not in self.workers:
            return False
        self.workers[wid].promotion = (new_position, new_rate)
        return True

    def pay(self, wid, start, end):
        w = self.workers.get(wid)
        if w is None:
            return None
        total = 0
        for s, e, rate in w.shifts:
            lo, hi = max(s, start), min(e, end)  # the part of this shift inside [start, end)
            total += max(0, hi - lo) * rate      # 0 when the shift is outside the window
            for ds, de in self.doubles:  # Level 4: double-pay minutes are paid once more
                total += overlap(lo, hi, ds, de) * rate
        return total

    # Level 4
    def add_double_period(self, start, end):
        if start >= end:
            return False
        for ds, de in self.doubles:
            if overlap(start, end, ds, de) > 0:
                return False
        self.doubles.append((start, end))
        return True

    7. Course registration: simplest timed-test answer. What makes it short:

    • Two defaultdicts do all the work. enrolled[course] is the set of students in it right now, and hist[(course, student)] is a list of (time, grade) entries. Neither needs an "if missing, create" line.

    • roster: build the graded list and the ungraded list separately, then concatenate. It's easier to get right than one clever sort key with None in it.

    from collections import defaultdict


class CourseRegistration:
    def __init__(self):
        self.cap = {}                     # course_id -> capacity (None = no limit); a course exists iff it is here
        self.students = set()
        self.enrolled = defaultdict(set)  # course_id -> students enrolled right now
        self.hist = defaultdict(list)     # (course_id, student_id) -> [(time, grade or None)]

    def _grade(self, cid, sid):  # current grade, or None
        return self.hist[cid, sid][-1][1]

    # Level 1
    def add_course(self, cid):
        if cid in self.cap:
            return False
        self.cap[cid] = None
        return True

    def add_student(self, sid):
        if sid in self.students:
            return False
        self.students.add(sid)
        return True

    def has_course(self, cid):
        return cid in self.cap

    def has_student(self, sid):
        return sid in self.students

    # Level 2 (Level 3/4 add `now`; Level 2 calls default it to 0)
    def register(self, cid, sid, now=0):
        if cid not in self.cap or sid not in self.students or sid in self.enrolled[cid]:
            return False
        if self.cap[cid] is not None and len(self.enrolled[cid]) >= self.cap[cid]:
            return False
        self.enrolled[cid].add(sid)
        self.hist[cid, sid].append((now, None))  # enrolled, no grade yet
        return True

    def set_grade(self, cid, sid, grade, now=0):
        if sid not in self.enrolled[cid]:
            return False
        self.hist[cid, sid].append((now, grade))
        return True

    def roster(self, cid):
        graded, ungraded = [], []
        for sid in self.enrolled[cid]:  # unknown course: an empty set
            if self._grade(cid, sid) is None:
                ungraded.append(sid)
            else:
                graded.append(sid)
        graded.sort(key=lambda sid: (-self._grade(cid, sid), sid))
        ungraded.sort()
        return graded + ungraded

    # Level 3
    def set_capacity(self, cid, limit):
        if cid not in self.cap or limit < 0:
            return False
        self.cap[cid] = limit
        return True

        if sid not in self.enrolled[cid]:
            return False
        self.enrolled[cid].remove(sid)  # frees the seat immediately
        self.hist[cid, sid].append((now, None))
        return True

    Rank repeated events

    Worked answer & why it works
    from collections import Counter

    """IDs ordered by frequency descending, then ID ascending; k <= 0 => []."""
    counts = Counter(events)

    02 · Requirement precision · 15 min

    Merge overlapping review windows

    Implement merge_windows(windows). Each pair is a half-open interval [start, end), with integer start < end. Input can be unsorted. Merge intervals only when they overlap; touching endpoints stay separate. Return sorted tuples; preserve the input.

    merge_windows([(5, 8), (1, 4), (3, 6), (8, 9)])
# [(1, 8), (8, 9)] — the final pair touches, but does not overlap
    Hint

    Sort a copy. Compare the next start to the end of the last merged interval. Does the spec require < or <=?

    Worked answer & regression cases
    def merge_windows(windows):
    """Merge overlapping half-open intervals; touching endpoints stay separate.

    Inputs have start < end. Do not mutate input. Return list of tuples.
    """
    result = []
    for start, end in sorted(windows):
        if result and start < result[-1][1]:
            result[-1] = (result[-1][0], max(result[-1][1], end))
        else:
            result.append((start, end))
    return result

    O(n log n) time and O(n) space. Test nested intervals, duplicates, negative endpoints, an empty list, and adjacent windows. Use the maximum end so a nested window cannot shorten a larger one.

class ReviewQueue:
    """Four-level original practice project. IDs/workers are nonempty strings.

    Priorities are nonnegative integers. Timed calls receive integer `now` in
    nondecreasing order globally. TTL and k are integers. No real clock needed.
    Expire leases at deadline <= now BEFORE any timed operation, even failures.
    L1/L2 methods are timeless; deleting a task also deletes its lease.
    """

    def __init__(self):
        self.tasks = {}
        self.leases = {}

    # Level 1: exact contracts and independent queue instances.
    def add(self, task_id, priority):
        if task_id in self.tasks:
            return False
        self.tasks[task_id] = priority
        return True

    def get(self, task_id):
        return self.tasks.get(task_id)

    def set_priority(self, task_id, priority):
        if task_id not in self.tasks:
            return False
        self.tasks[task_id] = priority
        return True

    def delete(self, task_id):
        if task_id not in self.tasks:
            return False
        del self.tasks[task_id]
        self.leases.pop(task_id, None)
        return True

    # Level 2: include leased tasks too, preserving this contract in later levels.
    def top(self, k):
        return self._rank(self.tasks, k)

    def _rank(self, ids, k):
        return sorted(ids, key=lambda key: (-self.tasks[key], key))[:max(0, k)]

    # Level 3: a lease is active for [now, now + ttl).
    def _expire(self, now):
        for task_id, (_, deadline) in list(self.leases.items()):
            if deadline <= now:
                del self.leases[task_id]

    def claim(self, task_id, worker, now, ttl):
        self._expire(now)
        if ttl <= 0 or task_id not in self.tasks or task_id in self.leases:
            return False
        self.leases[task_id] = (worker, now + ttl)
        return True

    def complete(self, task_id, worker, now):
        self._expire(now)
        lease = self.leases.get(task_id)
        if lease is None or lease[0] != worker:
            return False
        return self.delete(task_id)

    def ready(self, now, k):
        self._expire(now)
        return self._rank((key for key in self.tasks if key not in self.leases), k)

    # Level 4: validate the whole batch BEFORE taking any new lease.
    def bulk_claim(self, task_ids, worker, now, ttl):
        self._expire(now)
        if not task_ids or ttl <= 0 or len(set(task_ids)) != len(task_ids):
            return False
        if any(key not in self.tasks or key in self.leases for key in task_ids):
            return False
        for key in task_ids:
            self.leases[key] = (worker, now + ttl)
        return True

    Complexity: add/get/update/delete are average O(1). With n tasks and l leases, top costs O(n log n), expiry O(l), and ready O(l + n log n). Timed claim/complete cost O(l) with this scanning design; batch claiming b tasks costs O(l + b) average. State uses O(n + l) space. Sorting uses O(n) temporary space and batch duplicate checking O(b).

    The six mechanics, as code you can type from memory

    1 · Expiry. Store an absolute expires_at on the item, never a countdown. A value is alive while now < expires_at — which means it is dead at exactly timestamp + ttl, and that boundary is tested. Updating a value resets its expiry. Put the liveness check in one helper and call it at the top of every read.

    def _alive(self, item, now):
    return item.expires_at is None or now < item.expires_at

    2 · Scheduled effects. Cashback landing 24 hours later, a promotion at the next clock-in, a payment scheduled for a future time: keep them in a heap of (due_at, action) and, at the top of every operation, apply everything with due_at ≤ now before doing anything else. An operation at the exact due time must already see the effect.

    def _settle(self, now):
    # pending is a heap of (due_at, seq, apply); seq keeps equal due times orderable
    while self.pending and self.pending[0][0] <= now:
        _, _, apply = heapq.heappop(self.pending)
        apply()

    3 · Ranking with tie-breaks. Every Level 2 is a sort with a two-part key. Negate the number for descending, leave the name for ascending ties, slice for top N. Sort the whole list — a heap only pays for itself if a test times out, and none of these do.

    top = sorted(accounts.values(), key=lambda a: (-a.outgoing, a.id))[:n]
return [f"{a.id}({a.outgoing})" for a in top]

    4 · Snapshot, backup, restore. A backup is a deep copy of the live records with one change: store each item’s remaining TTL, not its absolute expiry, because restoring at a later time has to resume the countdown from the restore time. Finding “the latest backup at or before time T” is a bisect_right on the list of backup times.

    5 · Look-back queries. “What was this field at time T” means every write appends (timestamp, value, expires_at) to a per-field history, and a delete appends a tombstone. The query is a bisect_right to find the last write at or before T, then a check that the value was still alive at T. This is the one place the specification asks for a complexity bound, so no linear scans.

    6 · Merge, and re-creation. Fold the source’s state into the destination — balance, running totals, pending effects, remapped ids, a user’s files — then delete the source. The trap the tests plant: the same id created again later is a brand-new entity with nothing carried over. If your merge leaves any trace of the old id in another structure, that test fails.

    Two smaller ones ride along. Quota and capacity count only what is active right now, so they are computed, never stored. Version history is an append-only list per entity, and rollback copies an old entry forward as a new one rather than truncating.

    The structure that survives all four levels

    One design decision decides this test, and it is made before Level 1 is written: a class that owns all the state, one method per operation, shared checks in private helpers. Logic stranded in a dispatcher or a script passes Level 1 and then has nowhere to put Level 3.

    Two harnesses exist. Sometimes the platform hands you a class with method stubs to fill in, which is what recent sittings of this bank describe. Sometimes it hands you a list of operations as strings and a single function to implement. In the second case write the class anyway, and make the function a thin layer that reads the operation name, casts the arguments, calls one method, and formats the return value. The function stays dumb; the class holds the thinking.

    Take a timestamp on every internal method from the start, even while Level 1 ignores it. Level 3 then changes nothing about the shape of your code — it only starts using an argument that was already there. This one habit is worth more than any data-structure trick on this test.

    Problem A — file hosting service

    Source: CodeSignal’s public practice scenario. Not from your invitation, the role FAQ, or the Coachable brief — general preparation material.

    The public practice scenario. A remote file server: upload, read, copy, search, then lifetimes, then rollback.

    Level 1 · Initial design & basic functions

    FILE_UPLOAD(file_name, size) — upload to the server. If a file with the same name already exists, it throws a runtime exception.
    FILE_GET(file_name) — returns the size of the file, or nothing if it does not exist.
    FILE_COPY(source, dest) — copy source to a new location. If the source does not exist it throws. If the destination already exists it is overwritten.

    Hint — the decision this level is really testing

    Three different failure behaviours in three adjacent methods: upload throws on a duplicate, copy throws on a missing source but overwrites a duplicate destination, and get returns nothing. Write that asymmetry down before you implement it — it is the whole of Level 1’s score. Then ask the question that decides Levels 3 and 4: what does a file need to be, so that adding a creation time and a lifetime later is a field and not a rewrite?

    Worked answer & why it works
    class FileHosting:
    """Level 1 — Initial Design & Basic Functions.

    The whole score of the later levels is decided here, by ONE choice: a file
    is a RECORD, not a bare integer. Level 3 adds a timestamp and a ttl to every
    file and Level 4 has to rewind history; if `self.files[name]` is an int you
    rewrite every method to find out. Cost of the record now: nothing.
    """

    def __init__(self) -> None:
        # name -> {"size": int, "created": int|None, "ttl": int|None}
        self.files: dict[str, dict] = {}

    def file_upload(self, file_name: str, size: int) -> None:
        """Existing name is a runtime exception — NOT an overwrite."""
        if file_name in self.files:
            raise RuntimeError(f"file already exists: {file_name}")
        self.files[file_name] = {"size": size, "created": None, "ttl": None}

    def file_get(self, file_name: str) -> int | None:
        """Missing file returns nothing. Returning 0 is the classic wrong answer:
        0 is a legitimate size, so it collides with 'absent'."""
        record = self.files.get(file_name)
        return None if record is None else record["size"]

    def file_copy(self, source: str, dest: str) -> None:
        """Missing SOURCE raises; existing DEST is overwritten. The asymmetry is
        deliberate and is the single most-missed corner case at Level 1."""
        if source not in self.files:
            raise RuntimeError(f"no such source: {source}")
        self.files[dest] = dict(self.files[source])  # copy, never alias

    The data-model decision is the score. self.files[name] holds a record, not an int. Level 3 adds created and ttl to every file and Level 4 rewinds history; with a bare integer you rewrite all four methods under time pressure, and each rewrite risks the Level 1 tests you already passed.

    Two corner cases graders actually test. A 0-byte file is legitimate, so return 0-on-missing collides with a real answer — return None. And file_copy must deep-copy the record: self.files[dest] = self.files[source] aliases one dict from two names, so a later per-file ttl change silently mutates both.

    Level 2 · Data structures & data processing

    FILE_SEARCH(prefix) — find the top 10 files starting with the provided prefix. Order results by size descending, and in case of a tie by file name.

    Hint — the decision this level is really testing

    “Size descending, ties by name” is a mixed-direction sort. reverse=True reverses every key, which flips your tie-break the wrong way and produces output that looks right on data with no ties. How do you reverse exactly one key?

    Worked answer & why it works
    def file_search(self, prefix: str) -> list[str]:
    """Level 2 — Data Structures & Data Processing.

    Top 10 by size DESCENDING, ties broken by file name ASCENDING. That is a
    mixed-direction sort, so one `reverse=True` cannot express it: negate the
    numeric key instead and leave the string key ascending.
    """
    matches = [name for name in self.files if name.startswith(prefix)]
    matches.sort(key=lambda name: (-self.files[name]["size"], name))
    return matches[:10]

    Negate the numeric key; leave the string ascending. key=lambda n: (-size, n) is the only one-pass way to express two directions, because reverse=True would reverse the name too. This is the single most common silent Level 2 failure: it passes every test whose sizes are distinct and fails the one tie-break test.

    Slice after sorting, never before. [:10] on the sorted list is O(n log n); a heap would be O(n log 10) but you will not need it at these input sizes — and a wrong heap costs more time than a right sort. "abc".startswith("") is True, so an empty prefix correctly matches everything.

    Level 3 · Refactoring & encapsulation

    Files now might have a specified time to live. Implement extensions of the existing methods that inherit all functionality but take a timestamp, and where new files may specify a ttl — no ttl meaning an infinite lifetime.

    FILE_UPLOAD_AT(timestamp, file_name, file_size[, ttl]) — the file is available for ttl seconds.
    FILE_GET_AT(timestamp, file_name)
    FILE_COPY_AT(timestamp, file_from, file_to)
    FILE_SEARCH_AT(timestamp, prefix) — results should only include files that are still “alive”.

    Hint — the decision this level is really testing

    Resist writing a second, parallel set of *_at methods — that is two implementations of the same rules, and they will disagree before the 90 minutes are up. Put “is this file alive at time T?” in exactly one place. Then the question nobody asks until the test fails: when you copy a file that dies at t=100, when does the copy die?

    Worked answer & why it works
    # Level 3 — Refactoring & Encapsulation.
#
# Every operation gains a timestamp, and a file may carry a ttl. Do NOT fork
# a parallel set of *_at methods: express the untimed Level 1/2 calls in
# terms of the timed ones, or the two implementations drift and Level 1's
# tests start failing while you are working on Level 3.
def _alive(self, name: str, timestamp: int) -> bool:
    record = self.files.get(name)
    if record is None:
        return False
    if record["ttl"] is None:
        return True
    return timestamp < record["created"] + record["ttl"]

def file_upload_at(self, timestamp: int, file_name: str, file_size: int,
                   ttl: int | None = None) -> None:
    if self._alive(file_name, timestamp):
        raise RuntimeError(f"file already exists: {file_name}")
    self.files[file_name] = {"size": file_size, "created": timestamp, "ttl": ttl}

def file_get_at(self, timestamp: int, file_name: str) -> int | None:
    return self.files[file_name]["size"] if self._alive(file_name, timestamp) else None

def file_copy_at(self, timestamp: int, file_from: str, file_to: str) -> None:
    if not self._alive(file_from, timestamp):
        raise RuntimeError(f"no such source: {file_from}")
    source = self.files[file_from]
    # The COPY inherits the source's REMAINING life, not a fresh full ttl.
    remaining = None if source["ttl"] is None else source["created"] + source["ttl"] - timestamp
    self.files[file_to] = {"size": source["size"], "created": timestamp, "ttl": remaining}

def file_search_at(self, timestamp: int, prefix: str) -> list[str]:
    matches = [n for n in self.files if n.startswith(prefix) and self._alive(n, timestamp)]
    matches.sort(key=lambda name: (-self.files[name]["size"], name))
    return matches[:10]

    One predicate, one seam. _alive(name, timestamp) is the only place that knows the expiry rule, so “alive” cannot mean two different things in get and search. Expiry is timestamp < created + ttl — strictly less-than, so a file uploaded at 10 with ttl 20 is dead at exactly 30, not alive. Off-by-one here is worth several tests.

    A copy inherits the REMAINING life. Giving the copy a fresh full ttl lets it outlive its source, which no spec ever wants. Carry created + ttl - timestamp across.

    Uploading over a DEAD name must succeed. The duplicate check is “is a live file there”, not “is the key present” — an expired record is still sitting in the dict.

    Level 4 · Extending design & functionality

    ROLLBACK(timestamp) — roll the state of the file storage back to the state specified by the timestamp. All ttls should be recalculated accordingly.

    Hint — the decision this level is really testing

    Read the second sentence twice; it is the entire level. A file uploaded at t=10 with ttl=100 dies at 110. You roll back to t=50. Does it now die at 110, or at 150? One of those is “recalculated” and the other is “restarted”, and only one matches a rollback.

    Worked answer & why it works
    # Level 4 — Extending Design & Functionality.
#
# ROLLBACK(timestamp) restores the state as of that timestamp and says "all
# ttls should be recalculated accordingly". Read that clause twice: a file
# uploaded at 10 with ttl 100 must, after a rollback to 50, still expire at
# 110 — you rewind the WORLD CLOCK, you do not re-start the file's life.
#
# So keep the ORIGINAL created/ttl and simply drop anything not yet born or
# already dead at the rollback instant. Files whose created > timestamp never
# existed; files already expired stay expired.
def rollback(self, timestamp: int) -> None:
    for name in list(self.files):
        record = self.files[name]
        created = record["created"]
        if created is not None and created > timestamp:
            del self.files[name]          # not yet uploaded at that instant
        elif not self._alive(name, timestamp):
            del self.files[name]          # already expired at that instant

    You rewind the world clock, not each file’s life. The file still dies at 110. So the correct implementation preserves the original created and ttl and simply removes what did not exist at that instant: files whose created > timestamp (not yet uploaded) and files already expired by then. Restarting each survivor’s ttl from the rollback point is the intuitive reading and it is wrong — it makes rolled-back files outlive their original expiry.

    Level 4 is where the Level 1 record pays for itself. Because every file already carries its own created/ttl, rollback is a filter over self.files — about six lines. With a bare-integer model there is no created to filter on and this level is unreachable in the time left.

    Iterate over list(self.files), not the dict itself: deleting during iteration raises RuntimeError: dictionary changed size during iteration.

    Problem B — banking system

    Source: written by me in the ICA idiom from the community-reported scenario pool. Not from your invitation, the role FAQ, or the Coachable brief — general preparation material.

    A reported scenario pool. Accounts and transfers, then spend ranking, then deferred payments, then merging two accounts into one.

    Level 1 · Initial design & basic functions

    CREATE_ACCOUNT(timestamp, account_id) — returns True if the account was created, False if that id already exists.
    DEPOSIT(timestamp, account_id, amount) — returns the new balance, or nothing if the account does not exist.
    TRANSFER(timestamp, source_account_id, target_account_id, amount) — returns the source account’s balance after the transfer, or nothing if either account is missing, the two are the same account, or the source has insufficient funds.

    Hint — the decision this level is really testing

    This level returns values rather than throwing, so the shape of “no” matters: False, None and 0 are three different answers and the tests tell them apart. List the four distinct ways a transfer can be refused before you write it. And ask the Level 2/3/4 question now: what fields will an account need that it does not need yet?

    Worked answer & why it works
    class BankingSystem:
    """Level 1 — Initial Design & Basic Functions.

    Same discipline as Problem A: an account is a RECORD. Level 2 needs a
    running outgoing total, Level 3 needs scheduled payments, Level 4 needs to
    fold two accounts together. Every one of those is a field, not a rewrite.

    Note the return contract: a balance, or None for "could not do it". Do not
    raise here and do not return False — the tests distinguish 0 from None.
    """

    def __init__(self) -> None:
        self.accounts: dict[str, dict] = {}
        # (due_timestamp, scheduling_sequence, account_id, amount)
        self.scheduled: list[tuple[int, int, str, int]] = []
        self.next_payment = 1

    def create_account(self, timestamp: int, account_id: str) -> bool:
        if account_id in self.accounts:
            return False
        self.accounts[account_id] = {"balance": 0, "outgoing": 0}
        return True

    def deposit(self, timestamp: int, account_id: str, amount: int) -> int | None:
        self._run_due(timestamp)
        if account_id not in self.accounts:
            return None
        self.accounts[account_id]["balance"] += amount
        return self.accounts[account_id]["balance"]

    def transfer(self, timestamp: int, source: str, target: str, amount: int) -> int | None:
        self._run_due(timestamp)
        if source not in self.accounts or target not in self.accounts:
            return None
        if source == target:                 # a self-transfer is not a no-op, it is invalid
            return None
        if self.accounts[source]["balance"] < amount:
            return None                      # insufficient funds: NOTHING moves
        self.accounts[source]["balance"] -= amount
        self.accounts[source]["outgoing"] += amount
        self.accounts[target]["balance"] += amount
        return self.accounts[source]["balance"]

    Enumerate the refusals. Missing source, missing target, source == target, insufficient funds. A self-transfer is invalid, not a harmless no-op — treat it as a no-op and you both return the wrong value and, if you wrote the debit and credit as two steps, you can corrupt the balance.

    Refusal must be atomic. Check the balance before debiting. The natural imperative order — debit, credit, then notice the balance went negative — leaves money destroyed on a partial failure.

    Carry outgoing from the start. Level 2 ranks by total outgoing. One extra field maintained here turns that level into a sort instead of a history scan — and note that only a transfer counts as outgoing, never a deposit.

    Level 2 · Data structures & data processing

    TOP_SPENDERS(timestamp, n) — returns the n accounts with the highest total outgoing value, ordered by that total descending, ties broken by account_id ascending. Accounts that have never transferred still rank, with a total of 0.

    Hint — the decision this level is really testing

    Same mixed-direction tie-break as Problem A Level 2, and the same negate-one-key answer. The new trap is where the number comes from: if you compute each total by replaying transaction history at query time, this method is O(transactions) per call and you have also given yourself a second source of truth.

    Worked answer & why it works
    def top_spenders(self, timestamp: int, n: int) -> list[str]:
    """Level 2 — Data Structures & Data Processing.

    Top n by total OUTGOING descending, ties by account_id ascending. The
    trap is scoring this from transaction history at query time; keep the
    running total on the account (Level 1 already has the field) so this is
    a sort, not a scan. Accounts that never spent still rank, at 0.
    """
    self._run_due(timestamp)
    ranked = sorted(self.accounts, key=lambda a: (-self.accounts[a]["outgoing"], a))
    return ranked[:max(0, n)]

    Aggregate on write, sort on read. Level 1 already increments outgoing on every transfer, so this is a single sorted(…, key=lambda a: (-outgoing, a)). Deriving the total at query time is the version that breaks at Level 3, when scheduled payments also spend money and you must remember to teach the replay about them too.

    Never-spent accounts are in the ranking. “Top spenders” reads like “accounts that spent”, so filtering to non-zero totals is a tempting and wrong reading — they rank last at 0. Guard n as well: [:max(0, n)], because a negative slice bound silently returns items from the wrong end of the list.

    Level 3 · Refactoring & encapsulation

    Payments may now be deferred.

    SCHEDULE_PAYMENT(timestamp, account_id, amount, delay) — returns a unique payment id (payment1, payment2, …), or nothing if the account does not exist. The payment executes delay after timestamp.
    CANCEL_PAYMENT(timestamp, account_id, payment_id) — returns True if a not-yet-executed payment was cancelled, False otherwise.

    Payments falling due at the same instant execute in the order they were scheduled, and all due payments execute before the operation carrying that timestamp. A due payment whose account cannot cover it is skipped.

    Hint — the decision this level is really testing

    Nothing in this system has a clock of its own — time only advances because a caller passes a bigger timestamp. So where does a payment actually get executed? Find the one place that can be true for every method, including the ones you wrote at Level 1, and put it there instead of in eight of them.

    Worked answer & why it works
    # Level 3 — Refactoring & Encapsulation.
#
# Payments become deferred. The requirement that decides the score is
# ORDERING: when several payments come due at the same instant they execute
# in the order they were SCHEDULED, and they must run BEFORE whatever
# operation carried this timestamp. That is why every public method above
# opens with self._run_due(timestamp) — one seam, not eight copies.
#
# A due payment with insufficient funds is SKIPPED, not retried and not
# partially applied.
def schedule_payment(self, timestamp: int, account_id: str, amount: int,
                     delay: int) -> str | None:
    self._run_due(timestamp)
    if account_id not in self.accounts:
        return None
    sequence = self.next_payment
    self.next_payment += 1
    payment_id = f"payment{sequence}"
    # Keep the queue ordered by (due, scheduling sequence) so that payments
    # falling due at the SAME instant execute in the order they were made.
    self.scheduled.append((timestamp + delay, sequence, account_id, amount))
    self.scheduled.sort(key=lambda row: (row[0], row[1]))
    return payment_id

def cancel_payment(self, timestamp: int, account_id: str, payment_id: str) -> bool:
    self._run_due(timestamp)
    for row in self.scheduled:
        _due, sequence, owner, _amount = row
        if f"payment{sequence}" == payment_id and owner == account_id:
            self.scheduled.remove(row)
            return True
    return False                         # already executed, or not this account's

def _run_due(self, timestamp: int) -> None:
    while self.scheduled and self.scheduled[0][0] <= timestamp:
        _due, _sequence, account_id, amount = self.scheduled.pop(0)
        account = self.accounts.get(account_id)
        if account is None or account["balance"] < amount:
            continue                     # skip, do not retry, do not go negative
        account["balance"] -= amount
        account["outgoing"] += amount

    Every public method opens with self._run_due(timestamp). That is the seam the level is really testing: the requirement “due payments execute before the operation carrying this timestamp” has to hold for deposit and top_spenders too, not just for payment methods. Eight copies of that line is how the ordering tests start disagreeing with each other.

    Order by (due, scheduling sequence). Payment ids are strings, so sorting on the id sorts payment10 before payment2 — keep the integer sequence in the queue and format the id only for the caller.

    Skip, do not retry, do not partially apply. An unaffordable due payment is dropped; it must not go negative, and it must not linger and fire later. And a due payment is outgoing, so it counts toward Level 2’s ranking — which only works for free because both paths go through the same fields.

    Level 4 · Extending design & functionality

    MERGE_ACCOUNTS(timestamp, account_id_1, account_id_2) — merges account_id_2 into account_id_1. Returns True on success, False if either account does not exist or the two ids are the same. After a merge the absorbed id no longer exists, and everything it owned belongs to the survivor.

    Hint — the decision this level is really testing

    “Everything it owned” is doing a lot of work in that sentence. Before writing a line, enumerate every piece of state your class attaches to an account id — go and read your own __init__. Each one you forget is a separate test.

    Worked answer & why it works
    # Level 4 — Extending Design & Functionality.
#
# MERGE_ACCOUNTS folds account 2 into account 1. Enumerate what "merge"
# actually owns before writing a line — every field you forget is a silent
# partial-credit loss:
#   balance    summed
#   outgoing   summed, so Level 2's ranking stays correct afterwards
#   scheduled  re-pointed at the surviving id, keeping their due order
#   identity   the absorbed id must stop resolving entirely
def merge_accounts(self, timestamp: int, account_id_1: str, account_id_2: str) -> bool:
    self._run_due(timestamp)
    if account_id_1 == account_id_2:
        return False
    if account_id_1 not in self.accounts or account_id_2 not in self.accounts:
        return False
    absorbed = self.accounts.pop(account_id_2)
    survivor = self.accounts[account_id_1]
    survivor["balance"] += absorbed["balance"]
    survivor["outgoing"] += absorbed["outgoing"]
    self.scheduled = [
        (due, sequence, account_id_1 if owner == account_id_2 else owner, amount)
        for due, sequence, owner, amount in self.scheduled
    ]
    return True

    Enumerate from __init__, not from memory. Four things are keyed by account id, and each is its own test: balance (summed), outgoing (summed, so Level 2’s ranking is still right afterwards), scheduled payments (re-pointed at the survivor, keeping their due order), and identity (the absorbed id must stop resolving — a later deposit to it returns nothing).

    Forgetting outgoing is the classic partial-credit loss, because every merge test passes except the one that calls top_spenders afterwards — so it looks like a Level 2 regression and you go and debug the wrong level.

    Run due payments first. _run_due(timestamp) before merging, or a payment that was due at this instant executes against an account that no longer exists.

Likely questions

Seven questions this posting will produce

C1 · Safe autonomyThe bank question~2:30 answer

Design an agent that takes actions in an enterprise system, for example payments operations or dispute handling. How do you keep it safe?

Weak answers say "a system prompt telling it to be careful". The strong answer: the model proposes, code disposes.

least-privilege tools →authority in code →human gate on irreversible →idempotent + audited
Draft

“Start with the tool surface, not the prompt. Each tool is narrow, typed and scoped to the caller's entitlements. In Papercusp, authority is computed from a registry and enforced at dispatch; no prompt text can widen it. Actions split into reversible and irreversible. Irreversible ones, like moving money or sending anything outward, stop at a human gate. Destructive operations are dry-run unless you pass an explicit confirm. Every write carries an idempotency key so a retry can't double-post, and every call lands in an audit ledger with who, what and why. Autonomy is earned: shadow mode first, then approve-each, then autonomous on the low-risk slice the evaluation data supports.”

Probes

What about prompt injection through a retrieved document?
Retrieved text is data, never instructions. It can't grant tools, and the tool gate doesn't read the conversation.
How do you undo a half-finished multi-step action?
Compensating steps in a durable workflow (a saga) that resumes after a crash. See Sagas.
C2 · Resilience"Advanced error handling, intelligent routing"~2:00

An LLM provider starts returning 429s and timeouts mid-workflow. What happens in your system?

classify the error →retry only the retryable →fall back / route →durable resume
Draft

“First, classify: 429s, 503s and timeouts are transient; a 400 or a content refusal is permanent and retrying just burns money. Transient errors get bounded retries with jittered exponential backoff, and only for idempotent calls. Past the budget, route: Papercusp's inference gateway picks an account, keeps affinity for prompt caching, and fails over when one is rate-limited. Concurrency is capped so a burst can't stampede the provider. The workflow is durable, so a crash resumes from the last committed step instead of starting over. And a wait never sleeps forever: every await carries a timeout that wakes someone to check whether the thing it's waiting on is actually progressing.”

C3 · RAG"hybrid search, multivector retrieval"~2:30

Build a RAG assistant over internal policy documents. Walk me through it.

chunk + metadata →BM25 + dense →fuse + rerank →entitlements + citations →evaluate
Draft

“Chunk by document structure (sections, not fixed windows) and keep metadata: source, effective date, owner, access group. Retrieve two ways: BM25 for exact terms like policy numbers and acronyms, and dense embeddings for paraphrase. Fuse with reciprocal rank fusion, then rerank the top candidates with a cross-encoder. In a bank, filter by the user's entitlements before ranking, so the model can't be shown a document the user couldn't open. Answers cite their chunks, and a claim with no citation is dropped. Evaluate retrieval (recall@k) separately from generation (faithfulness to the retrieved text).”

Real lesson from Papercusp: RRF scores are rank-based. With k=60, a document ranked first in both lists scores 2/61 ≈ 0.033. We had a stats column mixing cosine scores and RRF scores, and a 0.45 relevance floor made it look like 99.9% of results were junk. It was a units bug: never threshold fused scores as if they were similarity.

Probes

Multi-vector retrieval?
Several vectors per document: per chunk with a parent-document return, per summary/question, or token-level late interaction (ColBERT). It trades index size for recall on long documents.
How do you keep it fresh?
Incremental re-index on document change events; the effective date in the metadata lets you answer "as of" questions.
C4 · Agent evaluation"CI/CD for agent evaluation"~2:00

How do you test an agent before it goes to production, and keep testing it after?

deterministic tests for tools →scenario evals →independent grading →gate + monitor
Draft

“Three layers. The tools are ordinary code with ordinary tests, and that's where most bugs live. Behaviour is covered by scenario suites: scripted conversations with a judged outcome, run in CI like any other test. Acceptance is a rubric written after the build, vetted, then graded by someone who didn't build it. In Papercusp the implementer literally can't self-grade. Nothing promotes unless the gate is green. In production, sample and grade live traces, and alert on drift in the grades, not just in latency.”

C6 · Latency & cost"profiling, caching strategies"~1:30

Your agent is too slow and too expensive. What do you do?

measure per step →shrink context →cache →route + parallelize
Draft

“Measure tokens and latency per step before touching anything; it's usually one step. Then cut context: Papercusp caps every tool result at about 1,500 tokens and lets the caller project just the fields it needs, which removed whole round-trips. Keep prompt prefixes stable so the provider's prompt cache hits. Route easy steps to a smaller model. Run independent tool calls concurrently. A semantic answer cache helps for repeated questions, but in a bank it must respect entitlements and freshness, or it becomes a data-leak path.”

C7 · KubernetesYour gap: bridge honestly~1:30

How would you deploy and scale this on Kubernetes?

Draft

“Papercusp runs on a single host under systemd, so I'll map from what I operate. Each agent process tree lives in a cgroup and is killed as a whole subtree. In K8s, that's the pod boundary. We distinguish 'dead' from 'slow' with heartbeats plus progress signals; those become liveness and readiness probes, and readiness should fail when the model provider is unreachable. Stateless API pods scale on request rate; agent workers scale on queue depth, not CPU, because they mostly wait on the model. Long jobs are Jobs with a durable workflow underneath. Secrets come from a vault, never the image. New agent behaviour ships behind a feature flag and a canary.”

Live-coding drill · Python

A resilient async LLM call path, from memory

Type this in about 15 minutes, talking as you go: what's retryable, why the jitter, why the semaphore. Runnable with tests: citi-async-drill.py (needs pip install fastapi httpx).

import asyncio
import random

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel


class TransientError(Exception):   # 429, 503, network blip: worth retrying
    pass


class PermanentError(Exception):   # 400, content filter, bad auth: retrying won't help
    pass


class AllProvidersFailed(Exception):
    pass


class ModelRouter:
    """Ordered fallback across providers, retries with jittered backoff,
    a per-call timeout, and a cap on concurrent calls (rate limits and cost)."""

    def __init__(self, providers, max_concurrency=8, timeout_s=20.0, retries=2, backoff_s=0.5):
        self.providers = providers  # each has: async complete(prompt) -> str
        self.sem = asyncio.Semaphore(max_concurrency)
        self.timeout_s, self.retries, self.backoff_s = timeout_s, retries, backoff_s

    async def complete(self, prompt: str) -> str:
        async with self.sem:
            last = None
            for provider in self.providers:              # routing = ordered fallback
                for attempt in range(self.retries + 1):
                    try:
                        return await asyncio.wait_for(provider.complete(prompt), self.timeout_s)
                    except (asyncio.TimeoutError, TransientError) as e:
                        last = e                         # jitter avoids a retry stampede
                        await asyncio.sleep(self.backoff_s * 2 ** attempt * random.uniform(0.5, 1.5))
                    except PermanentError as e:
                        last = e
                        break                            # don't retry; try the next provider
            raise AllProvidersFailed(repr(last))


async def run_tools(calls, timeout_s=10.0):
    """Fan out independent tool calls; one failure must not sink the others."""
    results = await asyncio.gather(*(asyncio.wait_for(c, timeout_s) for c in calls),
                                   return_exceptions=True)
    return [r if not isinstance(r, BaseException) else {"error": type(r).__name__} for r in results]


class Ask(BaseModel):
    prompt: str


def make_app(router: ModelRouter) -> FastAPI:
    app = FastAPI()

    @app.post("/ask")
    async def ask(body: Ask) -> dict:
        try:
            return {"answer": await router.complete(body.prompt)}
        except AllProvidersFailed:
            raise HTTPException(status_code=503, detail="all model providers unavailable")

    return app

Night-before refresh

Vocabulary they will expect you to use fluently

Transformer basics
Self-attention (queries, keys, values), positional encoding, decoder-only generation, the KV cache (why long contexts cost memory), and the context window versus retrieval.
Fine-tuning
SFT on examples; LoRA/QLoRA train small adapter matrices (QLoRA on a quantized base); DPO learns from preference pairs. Reach for RAG first when the problem is knowledge; fine-tune for format, tone or a narrow skill.
RAG terms
BM25, dense embeddings, hybrid search, reciprocal rank fusion, cross-encoder reranking, parent-document and multi-vector (ColBERT late interaction), recall@k, faithfulness.
Agent frameworks
LangGraph (StateGraph, nodes, conditional edges, checkpointers, interrupt); LangChain (chains, tools, retrievers); Google ADK (Agent Development Kit: agents, tools, multi-agent orchestration); MCP (a standard protocol that exposes tools to any model).
Bank governance
Model risk management (the US guidance is SR 11-7: validate, monitor, document every model); PII minimisation and data residency; audit trails; human sign-off for material decisions; escalate control gaps rather than work around them.
Python async
asyncio.gather(..., return_exceptions=True), wait_for timeouts, Semaphore for rate limits, TaskGroup (3.11+) for structured concurrency; FastAPI dependencies, Pydantic models, async def endpoints; never block the event loop with sync I/O.
